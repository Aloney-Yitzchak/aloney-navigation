# עבודה ב-GitHub

כל הפרויקט מנוהל במאגר אחד: הקוד, המטלות, ההחלטות והמסמכים. היסטוריית ה-Issues וה-Pull Requests היא התיעוד של התהליך, וחומר גלם לפרק הרפלקציה בתיק.

## מחזור החיים של מטלה

1. **Issue:** לכל מטלה יש Issue עם תיאור, דרישה מקושרת ותנאי סיום. אין עבודה בלי Issue.
2. **ענף:** מ-`main`, בשם `<סוג>/<מטלה>-<תיאור>`, למשל `feature/T13-dijkstra`.
3. **קומיטים:** קטנים, וכל הודעה מתחילה במספר המטלה: `T13: add priority queue`.
4. **Pull Request:** לפי התבנית — `Closes #14` (מספר ה-Issue, לא מספר המטלה: T13 הוא Issue 14), הפרומפט שבו השתמשנו, ואיך נבדק.
5. **בדיקות אוטומטיות:** GitHub Actions בונה את האפליקציה, מריץ את בדיקות היחידה, משווה כל מסך לתמונת ה-snapshot שלו, ומריץ את בדיקות הקבלה על אמולטור (Android 10 ו-14). PR שנכשל בבדיקה לא ממוזג.
6. **Code Review:** קוראים כל שורה, מריצים על טלפון, ומבקשים תיקונים בהערות על השורות.
7. **מיזוג:** Squash and merge. ה-Issue נסגר אוטומטית ועובר ל-Done בלוח.

## גרסאות להתקנה (Releases)

כל PR שמשנה את האפליקציה וממוזג ל-`main` הופך לגרסה בעמוד [Releases](https://github.com/Aloney-Yitzchak/aloney-navigation/releases), עם קובץ APK להתקנה בטלפון (הפעולה `Release`, בקובץ `.github/workflows/release.yml`).

- **מספר הגרסה** עולה בכל מיזוג: v0.1, v0.2 וכן הלאה. שם הגרסה הוא כותרת ה-PR, ויש בה קישור אליו.
- **הגדרות Firebase** נלקחות מסוד במאגר בשם `GOOGLE_SERVICES_JSON`, ולא מ-git. בלי הסוד הגרסה נבנית, אבל לא מסתנכרנת, וכתובה על כך אזהרה בגרסה.
- **מפתח חתימה משותף** (`app/shared-debug.keystore`) חותם את כל הגרסאות, וגם את מה שנבנה ב-Android Studio. טלפון מתקין עדכון רק אם הוא חתום באותו מפתח כמו האפליקציה שכבר מותקנת, ולכן גרסה חדשה מותקנת מעל הקודמת והמועדפים נשמרים. זה מפתח debug עם הסיסמה הציבורית הרגילה: הוא לא סוד, ואי אפשר להעלות איתו ל-Google Play.

> [!NOTE]
> **הערה לתלמידים:** המפתח במאגר מתאים לאפליקציה שמתקינים ישירות מ-GitHub. אפליקציה שמפרסמים ב-Google Play חותמים במפתח פרטי, שנשמר כסוד ולא נכנס לעולם ל-git.

## תוויות

- **שלב:** אחת מששת שלבי הפרויקט, כמו ה-Milestones.
- **סוג:** `type: docs`, `type: feature`, `type: data`, `type: ml`, `type: design`, `type: test`, `type: bug`.
- **דרישה:** `FR-01` עד `FR-13`, כך שאפשר לסנן את כל העבודה על דרישה אחת.
- **עדיפות:** `priority: must` או `priority: should`, לפי מסמך הדרישות.

## עריכת ה-Wiki

דפי ה-Wiki נשמרים במאגר, בתיקייה `wiki/`. משנים אותם כמו קוד: ענף `docs/`, Pull Request ומיזוג. אחרי המיזוג, הפעולה `Publish wiki` (ב-`.github/workflows/publish-wiki.yml`) מעדכנת את ה-Wiki אוטומטית. עריכה ישירה באתר תימחק בפרסום הבא.

## בינה מלאכותית ב-PR

- שום קוד לא נכנס ל-`main` בלי שהמפתח קרא והבין אותו.
- בכל PR מצורף הפרומפט שהוביל לקוד.
- קוד משמעותי מ-AI מסומן ב-Javadoc עם מספר מקור, ומופיע בביבליוגרפיה של התיק.
